# Cerebras SDK validation environment

Records what's needed to compile + simulator-run a CSL bundle on this node, plus
the smoke-test that confirms the toolchain is healthy.

## SDK install

- **Path:** `/home/USER/cs_sdk-1.4.0/`
- **Version:** Cerebras SDK 1.4.0 (per `Cerebras-SDK-1.4.0.tar.gz` in the install dir)
- **Container image:** `sdk-cbcore-202505010205-2-ef181f81.sif`
- **CSL extras:** `csl-extras-202505010205-2-d9070058.tar.gz` (canonical csl-examples at `/home/USER/csl-examples/`)
- **Wrapper scripts** (in `$CSL_SDK_ROOT`):
  - `cslc` — CSL compiler (singularity wrapper)
  - `cs_python` — Python interpreter that runs inside the container with the SDK runtime in scope
  - `sdk_debug_shell` — container shell + debugger
  - `csdb` — CSL debugger
  - `cs_readelf` — ELF reader for compiled binaries

## PATH setup

`cslc` and `cs_python` are not in `$PATH` by default. Either:

```bash
export PATH="/home/USER/cs_sdk-1.4.0:$PATH"
```

…or prefix each invocation. All examples below use the explicit prefix.

This repo's automation uses the same `PATH` prepend internally (see
`code_translation/ground_gotcha.py:_run_cslc` and the framework launchers).

## Bundle anatomy (what `cslc` + `cs_python` expect to find in a kernel dir)

```
kernel_dir/
├── layout.csl           # PE-grid definition, @set_tile_code, @export_name
├── pe.csl  (or pe_program.csl)  # per-PE compute file
├── run.py               # host-side driver: SdkRuntime, memcpy_h2d/d2h, launch,
│                        #   compare vs numpy reference, print SUCCESS
└── commands_wse3.sh     # invokes `cslc --arch=wse3 ...` then `cs_python run.py`
```

The compile output lands in `out/` (per the `-o out` flag). `cs_python` reads
`out/out.json` for compile-time params.

## Common per-kernel command (template)

For a 2x2 PE rectangle with fabric dims big enough for memcpy padding:

```bash
PATH="/home/USER/cs_sdk-1.4.0:$PATH" cslc \
  --arch=wse3 ./layout.csl \
  --fabric-dims=10,4 --fabric-offsets=4,1 \
  --params=W:32,H:32,WIDTH:2,HEIGHT:2 \
  -o out --memcpy --channels 1

PATH="/home/USER/cs_sdk-1.4.0:$PATH" cs_python run.py --name out
```

Fabric-dims rule of thumb: `--fabric-dims=(WIDTH+6),(HEIGHT+2)` is the minimum
that memcpy plumbing fits in. WSE-3's user-rectangle starts at `--fabric-offsets=4,1`
by convention (matches every csl-examples bundle).

## Notes

- The SDK runs inside Singularity, so first invocation per session has a
  small cold-start penalty (~5-10 sec). Warm: ~10-15 sec per compile, ~5-10 sec per
  cs_python invocation.
- Concurrent SDK invocations on the same node can wedge the container runtime.
  This repo's `code_translation/benchmark_csl.py:_singularity_gate` provides a
  file-lock to serialize them (opt-in via `XKERNEL_SINGULARITY_GATE=1`).
- The simulator is functional, not cycle-accurate by default; the timer module
  (`<time>`) provides timestamp-based cycle counts that are used as the canonical
  performance metric throughout this repo (see `cycles_send` in any kernel's
  `run.py`).
