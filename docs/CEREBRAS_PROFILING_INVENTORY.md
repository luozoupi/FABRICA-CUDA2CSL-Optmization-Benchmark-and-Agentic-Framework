# Cerebras WSE-3 Profiling & Instrumentation Inventory

## Summary

The ALCF Cerebras AI Testbed provides **12 profiling layers** spanning on-device timing,
simulator traces, ELF analysis, hardware dashboards, and agent-level reasoning logs.
We actively use 5 of these; 4 are implemented but default-off; 3 are completely unexplored.

## Active Layers (used in experiments)

### 1. TSC Cycle Timing (in-kernel)
- **Measures:** Total elapsed clock cycles for the timed compute window
- **How:** `timestamp.enable_tsc()` → `get_timestamp()` at tic/toc → host reads back
- **Access:** Baked into pe.csl + run.py; `benchmark_csl.py` extracts `cycles_send`
- **Sim/HW:** Both (HW has TSC enablement gotcha — some kernels report 12-27 cycles)
- **Status:** PRIMARY METRIC. Dead-timer guard catches missing `enable_tsc()`

### 2. sim.log Aggregate Stats
- **Measures:** `num_inst_dispatch`, `num_stalls_*`, `num_wavelets`, grid dims, total cycles
- **How:** Auto-generated by simulator; parsed by `_parse_sim_log()` in `profile_csl.py`
- **Access:** Produces bottleneck label: compute-bound / stall-bound / fabric-bound
- **Sim/HW:** Simulator only
- **Status:** ACTIVE — injected into optimizer prompt to guide angle selection

### 3. CTF Binary Traces (simfab_traces/stream0)
- **Measures:** Per-PE, per-cycle instruction traces. 7 event types:
  - `backpressure` — per-tile fabric link congestion
  - `dispatch` — instruction dispatch timeline with opcode names
  - `pipe` — pipeline stage execution
  - `switch_pos` — fabric switch reconfiguration
  - `wavelet_entry` — wavelet arrivals at PEs
  - `wavelet_trace` — individual wavelet flow with send/receive IDs
  - `debug_counters_wavelet` — per-PE per-color wavelet count summaries
- **How:** Binary CTF (barectf v3.0.1); parsed by `ctf_trace_parser.py` (no babeltrace2 needed)
- **Access:** Gate: `XKERNEL_TRACE_PROFILE=1` (adds ~1-2s overhead)
- **Sim/HW:** Simulator only
- **Status:** ACTIVE. Proven: Jacobi −11%, GoL −28% when optimizer sees per-PE feedback

### 11. Static Analysis Guards
- **Measures:** Pre-execution correctness checks
- **How:** `check_timing_integrity.py` (host-loop-inside-timer AST lint) + `_MIN_PLAUSIBLE_CYCLES` (dead-timer floor)
- **Sim/HW:** Both
- **Status:** ACTIVE — caught the immune-kernel bug and dead-timer gaming

### 12. Agent Reasoning Logger
- **Measures:** Per-optimization-step: `profiling_context` + `reasoning_reflection`
- **How:** Recorded in optimization_summary.json per kernel result
- **Sim/HW:** Both
- **Status:** ACTIVE since July 7 — enables post-hoc analysis of model behavior

## Implemented but Default-Off

### 4. ELF Memory Profiling (cs_readelf)
- **Measures:** Per-PE SRAM usage (bytes used vs 48KB ceiling)
- **How:** `cs_readelf --ms` on compiled ELFs; parsed by `_run_cs_readelf()` in `profile_csl.py`
- **Access:** Gate: `XKERNEL_PROFILE_MEMORY=1`
- **Sim/HW:** Both (works on any compiled ELF)
- **Extra:** `--routing` (routing tables), `--switching` (switch configs), `--sym` (symbol table) — UNEXPLORED

## Unexplored (Available but Not Integrated)

### 5. csdb Interactive Debugger
- **Measures:** PE memory read/write, register inspection, trace examination, wavelet dumping
- **How:** `/home/USER/cs_sdk-1.4.0/csdb` — interactive or scriptable
- **Sim/HW:** Simulator (post-mortem); HW via CM connection (untested)
- **Potential:** Deep post-mortem on why specific multi-PE kernels deadlock

### 6. debug_util Post-Mortem Symbol Reader (Appliance SDK)
- **Measures:** Read any PE's runtime variable values after simulation
- **How:** `debug_util(artifact, sdkruntime).get_symbol(col, row, 'var', np.float32)`
- **Sim/HW:** Simulator only (asserts `is_simulator()`)
- **Potential:** Diagnose data distribution issues in multi-PE kernels

### 7. Hardware Artifact Download
- **Measures:** Post-execution debug artifacts from real WSE-3 runs
- **How:** `SdkRuntime.download_artifact(name, path)` or `SdkLauncher.download_artifact()`
- **Sim/HW:** Hardware only
- **Potential:** Retrieve hardware-level PE traces for real silicon comparison

### 8. Grafana Cluster Dashboards
- **Measures:** Per-job PE utilization, timing, system metrics
- **How:** `https://grafana.REDACTED.cerebras.internal/d/WebHNShVz/wsjob-REDACTED?var-wsjob=<JOB_ID>`
- **Access:** SSH SOCKS proxy (`ssh -D5555 cerebras.alcf.anl.gov`) + browser proxy
- **Sim/HW:** Hardware only
- **Potential:** Visual PE utilization heatmaps for hardware runs

### 9. csctl Log Export
- **Measures:** Full job logs + compile artifacts + binary debug artifacts
- **How:** `csctl log-export <wsjob-ID> -b -c -p <path>`
- **Sim/HW:** Hardware only
- **Potential:** Most promising path to hardware-level profiling data

### 10. Global Performance View (Perfetto Traces)
- **Measures:** TTFL, network errors, step timing (ML-training oriented)
- **How:** `GPVTraceWriter` in appliance SDK → Perfetto UI
- **Sim/HW:** Hardware only
- **Potential:** Uncertain for single-kernel CSL profiling; designed for training workflows

## Key Gaps

1. **No hardware-side per-PE traces** — sim.log/CTF/debug_util are simulator-only
2. **csctl log-export + download_artifact** could fill this gap but are untested
3. **Grafana dashboards** are accessible but nobody has examined the per-job PE metrics
4. **csdb** could diagnose multi-PE deadlocks but requires interactive or scripted use
