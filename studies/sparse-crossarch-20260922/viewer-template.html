How the work would be distributed across WSE PEs

Equal contiguous row ranges

Balance whole rows by nonzeros

A lower maximum nonzero count can shorten the compute tail, but row reassignment can increase dense-row replication. These predictions count each distinct B row once per PE. They exclude routes, link contention, partial-result reduction and temporary storage. A row longer than the per-PE target cannot be balanced without splitting its reduction.

What these measurements can explain

Reuse has a cost

GPU row caching can reduce load requests while adding synchronization and instructions. On WSE, copying already-local CSR metadata can have a similar tradeoff. Compare complete implementations and inspect counters before calling an operation memory-bound.

Width determines the parallel work

SpMV has one accumulator per row. SpMM reuses each index and value across many output columns. A warp or CSL descriptor should exploit that width without exhausting registers, SRAM or instruction memory.

Density is not a sufficient workload description

Rows, columns, nonzero count, row-length variation, column locality, output width and repeated uses each change the implementation choice. Balanced local arithmetic can still be limited by remote operand delivery.

Correctness and unsuccessful choices remain visible

Failed fixed-tolerance checks are excluded from timing comparisons. Simulator timeouts are distinct from numerical or compiler failures. Source changes that leave timing unchanged are useful negative evidence.
