# Piece-3D Live Run: Immune Kernels Report

## 1. Headline

**Multi-file planner unblocked 0 of 4 immune kernels. 0 of 4 won.**

Across BiCGSTAB, Conjugate_Gradient, Preconditioned_CG, and Power_Method, the
`_attempt_round_multifile` path never fired (grep for the `"multi-file: focus=..."`
marker returned 0 hits in every log). All 12 rounds (3 per kernel) were
rejected; the legacy single-file path edited only the root dispatcher on every
attempt. `blas.csl` was edited on **0** of 4 kernels.

The Piece-3D infrastructure is plumbed and the planner did run fresh under
`claude-opus-4-7` on every kernel, but the planner emitted
`len(focus_files) == 1` in all four cases, so `_is_multifile()`
(optimize_explore.py:758-762) routed every round back to the legacy path.

## 3. What Proved the Architecture Works

Concretely, **not much in this batch**. What did get exercised:

- The freshly-deleted plans were regenerated by `claude-opus-4-7` on all four
  kernels (one HTTP planner call each, recorded in
  `/home/USER/xkernel/knowledge/explored/optimization/plans/{bicgstab,conjugate_gradient,preconditioned_cg,power_method}.json`).
- Planner rationales correctly identified `blas.csl` as the high-density
  helper (10-11.1%) on CG, PCG, BiCGSTAB, and Power_Method, and exposed it
  read-only in `expose_in_prompt`.
- The optimizer loop ran cleanly end-to-end on every kernel (compile + bench
  passes, 12 experience rows appended to `experiences.jsonl`, no timeouts, no
  provider failures after switching to the `xkernel-agent` micromamba env).
- Auto-mode OPEN switchover after 2 consecutive rejects worked on all four
  kernels (round 3 angle = `OPEN` in every case).

What was **not** validated:

- `blas.csl` edited on **0** kernels.
- `_attempt_round_multifile` invoked on **0** kernels.
- Multi-file staging / failure-artifact layout (only `last_pe.csl` shows up in
  artifacts; no helper-file sibling was ever staged).

So while the planner, the runner, and the experience store are healthy, the
specific Piece-3D claim ("the optimizer can now edit helpers like
`blas.csl`") remains **unproven on real kernels**.

## 4. What's Still Broken or Unclear

1. **Planner under-specifies `focus_files`.** On all four kernels the planner
   chose either `['src/<root>.csl']` (BiCGSTAB, PCG) or `['src/blas.csl']`
   alone (CG, Power_Method). Neither shape trips `_is_multifile()` (requires
   `len > 1`). The planner's *rationale* is often correct — it names
   `blas.csl` as the hot helper — but the *output list* is wrong.

2. **Single-file path ignores `plan.focus_files[0]` when it disagrees with
   `target.target_relpath`.** On Conjugate_Gradient the planner set
   `focus_files=['src/blas.csl']` and `Power_Method` did the same, yet the
   single-file path edited the root dispatcher (`kernel_cg.csl` /
   `kernel_power.csl`) anyway. That is silently dropping the planner's
   intent. Two reasonable fixes: honor `focus_files[0]` in the single-file
   path, or fail-loud when it disagrees with the dispatcher.

3. **No-improvement gate vs. dispatcher-identity rewrites.** When the LLM is
   pointed at a thin orchestrator (e.g. Power_Method's `kernel_power.csl`,
   density 0.0%), it tends to emit semantic no-ops that produce
   `cycles_send == baseline` exactly. This is a symptom of #2 — the model is
   being asked to optimize the wrong file.

4. **Planner non-determinism across sibling kernels.** Same model
   (`claude-opus-4-7`), same provider, same family of kernels (CG / PCG /
   BiCGSTAB all call into `blas.csl`), but the planner only put `blas.csl`
   into `focus_files` on CG and Power_Method (and only as a singleton). PCG
   and BiCGSTAB got the dispatcher-only list. The planner prompt is not
   reliably producing the multi-file shape even when its own rationale calls
   for it.

5. **`blas.csl`-only focus is itself suspect.** If the planner picks
   `focus_files=['src/blas.csl']` alone (no dispatcher), the optimizer would
   need to re-bench the kernel-level cycle count without touching the entry
   point — that workflow is untested. Even if `_is_multifile()` is relaxed
   to fire on `len >= 1`, the prompt template still needs the dispatcher in
   context as a read-only reference.

## 5. Recommended Next Move

**Step 1 (one-line fix, run today): tighten the planner prompt to require
both the dispatcher AND the hot helper in `focus_files` whenever rationale
mentions the helper.** Concretely, add an explicit rule to
`prompt_cuda2csl.py` (or wherever the planner prompt lives) along the lines
of: *"If you identify a helper file as the hot path, `focus_files` MUST
contain both the root dispatcher and the helper. Single-element lists are
only acceptable when no helpers participate."* Then delete the four cached
plans and re-run the same four kernels. Expected outcome: at least 3 of 4
trip the multi-file path.

**Step 2 (defensive, parallel): make the single-file path honor
`plan.focus_files[0]` when it is not the dispatcher.** Today's behavior
(silently editing the root anyway) hides planner mistakes and produced the
identity-rewrite results on CG / Power_Method. Either honor the planner's
choice, or refuse to run and log a clear "planner asked for X, dispatcher
is Y" error so the next iteration sees the disagreement.

After both steps, re-run the 4 immune kernels and look for: (a) non-zero
`multi-file: focus=...` markers in the logs, (b) `last_pe.csl` plus a sibling
helper file in failure artifacts, and (c) any speedup > 1.01x on a round
where `blas_csl_edited == true`.
